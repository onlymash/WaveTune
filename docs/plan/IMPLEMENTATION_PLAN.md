# 无线耳机 Linux 客户端实施计划（移植自 EncoDeck）

## 目标与范围

本项目目标是将 [EncoDeck](https://github.com/TIANLI0/EncoDeck) 移植到 Linux 桌面，使用 Rust 与 GTK4/Libadwaita
构建现代化的原生界面，通过 BlueZ 与各品牌已配对的蓝牙无线耳机通信。

项目初期针对欧加体系（OPPO、OnePlus 和 realme）耳机完成适配，并已成功接入首个扩展品牌 EarFun（GAIA V3 架构，涵盖 EarFun Air Pro 4、Free Pro 3、Air S）。当前界面聚焦设备状态、降噪、EQ 预设及耳机已配对设备管理。
底层架构已全面完成多品牌隔离重构，使用品牌名称作为分类，将协议、配置与会话区隔在独立命名空间中，为未来扩展华为、小米、
vivo、漫步者等多品牌耳机支持奠定基础。

协议依据见 [OPPO 蓝牙 API 记录](../api/OPPO_BLUETOOTH_API.md) 及 [EarFun 蓝牙 API 记录](../api/EARFUN_BLUETOOTH_API.md)。协议为非官方私有协议，开发时应持续区分设备实测、客户端配置推断和设备动态上报的能力；
功能开放依据型号兼容配置及设备能力/支持列表，不以真机验证作为额外开关条件。

## 首版明确不做

- 不实现固件升级/OTA、协议扫描、未知命令写入。
- 不自行配对或连接未连接的耳机；用户先使用 Linux 蓝牙设置配对并建立连接。
- 不为未知产品 ID 开放型号专属查询或写入；未知型号只执行握手与产品识别。
- 不在日志、崩溃报告中记录蓝牙地址、序列号或耳机推送的其他设备列表。
- 不把设备能力/支持列表未确认的功能显示为可用；兼容目录定义与硬件验证证据分开记录。

## 技术方案

### 分层

```text
GTK4 UI (gtk4-rs)
        │ typed view-model/events
Application state + command orchestration
        │
OPPO protocol (framing, parser, models, session, read/write confirmation)
        │ async byte channel
Linux Bluetooth adapter (BlueZ D-Bus + RFCOMM socket / SDP)
```

- **UI**：`gtk4-rs`，使用 GTK/GLib 主循环；所有蓝牙 I/O 放到异步任务/后台线程，结果通过
  GLib channel 或 `gio::` 集成回 UI 线程，避免阻塞窗口。
- **设备管理**：BlueZ D-Bus (`org.bluez`) 枚举已连接的 OnePlus/OPPO/realme 耳机，以设备类别和
  Bluetooth Company ID 筛选（不以名称或 `Modalias` 判断品牌）；OPPO 设备也可由已验证控制
  服务 UUID 识别。应用启动时发现，自动连接首个提供控制服务的候选，其他候选可由用户选择切换，并定期刷新列表。
  连接前通过 SDP 的 `ELNK` SPP 服务解析 RFCOMM 通道，不猜测通道或选择任意服务；未发现匹配
  服务时返回错误。不会自行配对或建立 OS 蓝牙/音频连接。
- **协议核心**：独立 Rust 模块，不依赖 GTK；实现帧编解码、粘包/半包解析、分片重组、
  请求序列关联、超时、响应状态、事件订阅及 Enco X4 命令编解码。
- **状态模型**：所有展示值都有“已确认/未知/过期”语义；写入采用发送、确认、回读的状态机，
  未成功前不乐观更新界面。
- **配置与日志**：使用 XDG 配置/状态目录；结构化日志默认不含设备标识，不记录原始敏感
  事件帧。诊断导出必须先脱敏。

具体 Rust 蓝牙 crate 与 SDP 接口在技术验证阶段选型；优先采用可维护、可异步取消且不会
阻塞 GTK 主循环的方案，并保留可替换的 `BluetoothTransport` trait。

## 里程碑与验收

### 0. 工程与平台验证

- 建立 Cargo workspace：`encocore`（协议/领域逻辑）、`encobluetooth`（Linux 适配器）、
  `encogtk`（应用 UI）；单仓结构可按项目规模简化，但协议不能耦合 UI。
- 确认 GTK4、BlueZ、Rust 工具链安装及最低支持发行版；验证 D-Bus 枚举设备和 RFCOMM
  通道连接权限。
- 对 Enco X4 验证 SDP 服务 UUID/通道、连接、断开和应用退出清理。

**完成标准：** 能安全枚举用户已配对设备；能连接 X4 控制 RFCOMM 通道并收发字节；连接失败
时有可读错误，不影响 UI 响应。

### 1. 协议核心

- 实现可增量消费的帧解析器，覆盖长度 varint、多个连续帧、分段输入、非法头恢复及分片
  重组；严格校验长度上限。
- 实现应用包编码/解码、命令响应关联、状态码解析、3–5 秒可配置超时及断连取消。
- 实现握手、产品 ID、事件能力查询/订阅；遵守 capability bitmap。
- 用协议文档中的电量示例和新增的边界用例建立单元测试与 mock byte channel 集成测试。

**完成标准：** 无需真机即可验证协议字节级测试；半包/粘包/畸形输入测试不会崩溃、无限
缓冲或错误地将未确认数据标记为成功。

### 2. Enco X4 只读 MVP

- 加入 X4 产品定义和型号专属降噪索引表。
- 查询固件、电量、佩戴状态、当前降噪状态；订阅并解析电量、佩戴、降噪变化事件。
- GTK4 主窗口展示设备、双耳/盒电量、充电状态、连接状态、固件与当前降噪模式。
- 盒子电量暂缺时保留最近一次已知值并显示读取时间，不伪造实时状态。

**完成标准：** 在 Enco X4 真机上，初次查询与耳机/手机侧状态变化可同步；盒子断续上报时
行为符合协议记录；重新连接后状态重建正确。

### 3. 降噪写入（X4 已实现，兼容目录已导入）

- UI 提供关闭、降噪、通透、自适应四种主模式；选择降噪或自适应时显示相应子模式。
- 优先使用 `0x010C` 子类型 3 获取支持模式；若设备未返回可用清单，则使用型号配置并标示来源。
- 已导入型号的模式按各自型号配置、设备能力与运行时支持列表开放；每次设置仍须通过 ACK
  与回读确认后才更新 UI。
- 写入前检查型号和 capability bit 8；发送设置后等待确认并回读；处理中途断连、耳机未佩戴、
  耳机忙及低电量错误。
- 失败时保留旧状态并显示原因，不进行成功态回滚假象。

**完成标准：** 代码侧的支持列表解析/回退、模式掩码、能力位和回读规则有单元测试；设备返回的
模式清单用于决定可用选项；外部触控/手机切换仍能更新 UI。新导入型号的硬件覆盖需分型号验证。

### 4. 稳定性与桌面体验

- 处理 BlueZ 设备消失、断连、睡眠/唤醒、蓝牙适配器重启；支持自动发现已连接设备、
  多设备选择、设备切换及用户触发刷新/重连。
- 提供连接错误、缺少系统依赖和权限不足的可操作提示；关闭窗口、取消异步任务与释放
  socket 的生命周期清晰。
- 添加键盘导航、无障碍标签、系统深浅色适配和至少简体中文/英文文本资源。
- 托盘/后台常驻已完成：基于现有 `gio::DBusConnection` 导出 StatusNotifierItem + DBusMenu，复用降噪写入门控与后台会话状态；GNOME 需安装 AppIndicator and KStatusNotifierItem Support 扩展，其他 SNI 桌面原生兼容。

**完成标准：** 连续断连/重连无死锁、重复订阅或后台泄漏；桌面主循环保持响应。

### 5. 更多型号与发行

- 为型号表、协议解码和设备状态建立 fixture 测试；每个新型号按其产品 ID、设备能力和支持列表
  配置可用功能，未知型号保持只读。
- 加入兼容性表，标注操作系统/BlueZ/耳机型号/固件及证据等级。
- 选择发行格式（优先 Flatpak 或 distro 包的可行性评估），记录 GTK4、BlueZ 运行依赖；
  提供构建、测试和打包 CI。
- 发布前审查依赖许可证、隐私说明、错误处理与日志脱敏。

**完成标准：** 构建可复现；干净 Linux 环境按说明安装运行；兼容性声明不超出实际验证结果。

## 测试策略

1. **单元测试**：帧/包字节序、varint 边界、分片、不同命令 payload、降噪掩码、错误码。
2. **模拟传输测试**：响应错序、重复响应、超时、部分写入、EOF、恶意超长 LEN、未知事件。
3. **D-Bus/BlueZ 集成测试**：设备枚举、连接状态通知、适配器缺失、断连与取消。
4. **硬件验证**：对设备报告支持的模式执行单项写入和回读；记录型号/固件，不保存
   原始个人设备信息。
5. **UI 验收**：连接/断开/未知状态/错误状态、无盒电量、外部状态变化、键盘操作。

## 主要风险与处理

| 风险 | 应对 |
|---|---|
| 私有协议随型号/固件变化 | 型号配置与协议实现分离；未知型号只读；记录证据等级。 |
| RFCOMM 通道/BlueZ 状态在不同发行版表现不一 | 先做 Linux 技术验证；用 D-Bus/SDP 确定服务；提供清楚的依赖和故障提示。 |
| 通信异步事件与请求响应交错 | 单一会话协调器负责序列、超时和事件分发；覆盖乱序及重复消息测试。 |
| 写入失败但 UI 显示成功 | 只展示耳机确认并回读后的状态；错误保留旧确认值。 |
| 日志包含其他已配对设备信息 | 默认不记录原始帧；地址和名称脱敏；报告导出由用户显式触发。 |
| GTK 主线程被蓝牙操作阻塞 | I/O 后台执行，使用可取消任务，将状态变更派发到 GTK 主上下文。 |

## 建议开发顺序

先完成里程碑 0 的 Linux 蓝牙最小验证，再进入协议核心和只读 MVP。设置控制根据型号兼容配置、
设备能力和支持列表开放；其他型号、复杂 EQ/手势配置留到后续版本。
